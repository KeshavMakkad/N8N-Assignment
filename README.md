# Negative Review Analysis — Agentic Workflow

An n8n workflow that automates negative customer review analysis for a D2C skincare brand. Built to replace a manual process of downloading CSVs, filtering in Sheets, and pasting into Claude.

## The Problem

I work at Reginald Men, a men's grooming brand under Honasa Consumer. I was asked to go through all the negative reviews on our Shopify store, figure out what customers were complaining about, and put together some kind of analysis for the team.

What I was doing at the time: download the reviews, filter them in Google Sheets, paste them into Claude, read the output, pass it along. Claude did the job fine but the whole thing was manual, inconsistent, and completely dependent on me doing it right every time.

This workflow automates that entire process.

---

## What It Does

1. User submits a Google Sheets URL through a form
2. Workflow pulls reviews and product data from the sheet
3. Filters to negative reviews — deterministic, rating threshold
4. Classifies each review into an issue bucket — AI
5. Generates analysis on what's going wrong and why — AI
6. Sends an approval form to a human before anything gets written
7. On approval, writes the full report to a Google Doc
8. Redirects to the doc

---

## Workflow Structure

```
Form Trigger → URL Parser → Fetch Reviews + Products → Merge → Filter
→ [Classification Agent] + [Insights Agent] → Merge → Result Parser
→ Human Approval → IF → Google Doc Report → Redirect
```

See [workflow.md](./workflow.md) for the full node-by-node breakdown.

---

## Issue Buckets

The classification agent puts each review into one of these:

- Delivery / Logistics
- Packaging
- Skin Reaction
- Efficacy / Results
- Texture / Consistency
- Smell / Fragrance
- Price / Value
- Authenticity
- Customer Service
- Other

| Google Docs | Report output |
| Gmail | Approval notification |

---

## Where AI Is Used and Where It Isn't

AI is used in exactly two places — classifying reviews into buckets, and generating insights on what's going wrong. Both of these need actual reasoning.

Everything else is just code — filtering by rating, joining datasets, batching, routing on approval. These have one correct answer and don't need an LLM.

See [workflow.md](./workflow.md) for the full breakdown.

## Dataset

Using the [Sephora Products and Skincare Reviews](https://www.kaggle.com/datasets/nadyinky/sephora-products-and-skincare-reviews) dataset from Kaggle for the demo. In production this would connect directly to the brand's Shopify or Judge.me review export.

## Known Limitations

- Capped at 25 reviews per run because of Groq's free tier limits
- Google Doc output is plain text, no formatting or charts
- The approval form doesn't show a preview of the insights before you approve

## What I'd Build Next

- Slack integration so approvals happen in Slack instead of a form
- Bump review volume with a paid API key
- Add a retry node for when the LLM hits rate limits
- Google Sheets output alongside the Doc so the team can filter by bucket
